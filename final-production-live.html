Zoventro: Final Production Go-Live Audit

Repo /opt/homebrew/var/www/p · branch main · HEAD 7808723 · Date 2026-11-10 · Scope: Laravel admin + legacy API, Node/Express API + Socket.IO (apis/), React frontend (frontend/), config, dependencies.

Method: read-only code review, plus local checks (type-check, npm audit, composer audit, and Laravel route matching via tinker). No code was changed. Secret values are never shown: only where they are and that they exist.

Verdict: NOT READY for production live.

Three issues each block release on their own:

  1. The OTP is still fixed at 123456, so anyone can log in as any organizer or participant knowing only an email.
  2. Real secrets (JWT, DB, SMTP, Razorpay) sit in a git-tracked file.
  3. Any admin can read server files such as .env through showImage path traversal.

Most of the October audit (production-index.html) is still open. The API rate limiter also has a functional bug: behind nginx every user shares one IP bucket, so a real event will hit HTTP 429 after about 15 joins.

Issue list

P-01

OTP generator returns a fixed code 123456 for every organizer and participant login

CriticalStill open (ZV-001)
Where
apis/src/utils/otp.ts:19: return '123456'; sits before the real crypto.randomInt line, which is unreachable. Used by organizer register/login/resend and participant join/resend.
Impact
Full account takeover. Call POST /v1/organizer/login with the victim's email, then /verify-login with otp=123456, and you get a valid 24h JWT. You can then see bookings, invoices and billing/GST data, reschedule events and download result PDFs. The same works for any participant seat.
Fix
Delete line 19 so crypto.randomInt(0, max) runs. Add a per-account failed-attempt counter that clears the OTP after 5 wrong tries.
P-02

Legacy Laravel /api/v1 auth and game-join also use fixed OTP 123456

CriticalStill open (ZV-005)
Where
app/Http/Controllers/API/AuthController.php:32, 111; app/Http/Controllers/API/GameJoinController.php:97 (comment: "TEMP … revert before production"). Routes are still live in routes/api.php:20-31. game-join has no throttle.
Impact
A second account-takeover path through the old API, even after P-01 is fixed.
Fix
If the React app no longer uses these routes, remove them from routes/api.php. Otherwise use random_int(100000, 999999) and add throttle:6,1 to game-join.
P-03

Real secrets committed in a tracked file, and private keys and env files in git history

CriticalStill open (ZV-004)
Where
apis/DB_HOST=127.0.0.1 (an env file saved with a wrong name) is tracked in git. It has 5 non-empty secret entries: JWT_SECRET, DB_PASSWORD, MAIL_PASSWORD, RAZORPAY_KEY_SECRET and RAZORPAY_WEBHOOK_SECRET. Git history also holds .env, frontend/.env, frontend/txt-env, production.txt, the SSH keys amigo/amigo.pub and storage/oauth-private.key.
Impact
Anyone with repo access can forge organizer JWTs, log in to the DB and SMTP, and call Razorpay with your key. Payments could be refunded and fake webhooks would pass verification.
Fix
Run git rm --cached "apis/DB_HOST=127.0.0.1", then rotate every secret. Removing the file does not undo the exposure. Optionally scrub history with git filter-repo and force-push.
P-04

Admin showImage path traversal can read any file, including .env

HighNew
Where
app/Http/Controllers/Admin/HomeController.php:269-299; route routes/admin.php:43 showImage/{a}/{b?}/…
Proof
Through tinker, /admin/showImage/%2e%2e/.env and /admin/showImage/../.env both match the route with a="..". public_path("/../.env") exists and has an extension, so the code would return the file. The file itself was not read.
Impact
Any logged-in admin user, including a low-permission sub-admin (there is no RBAC here), can download .env with the DB, mail, Razorpay and APP_KEY secrets. With APP_KEY they can forge session cookies.
Fix
Reject any segment equal to ... Resolve with realpath(), check it starts with public_path('uploads'), and allow-list image extensions.
P-05

Booking details, including the invitation link and organizer email, served without login

HighStill open (ZV-003)
Where
GET /v1/organizer/booking/:booking_id: organizerRoutes.ts:155-158, organizerController.ts:366-403 (no authMiddleware)
Impact
Booking IDs are sequential. Looping 1…N returns every customer's company, organizer email, package and price, plus the invitation_link, which lets an outsider join any event.
Fix
Add authMiddleware and WHERE ob.organizer_id = req.user.id.
P-06

create-booking and complete-booking are unauthenticated and trust the client's organizer_id / booking_id

HighStill open (ZV-009)
Where
organizerRoutes.ts:140-185; organizerController.ts:309 (organizer_id taken from the body) and :422
Impact
Anyone can create bookings for any organizer. They can also complete someone else's pending booking, writing their own billing and GST details, or choose cod, which activates the booking with no payment.
Fix
Add authMiddleware and take the organizer id from the JWT. In completeBooking, check booking.organizer_id === req.user.id.
P-07

Event-stats IDOR: any organizer, or any anonymous socket, can read another booking's participant names and emails

HighStill open (ZV-008, ZV-002)
Where
organizerController.ts:237-246 getEventStats has no ownership check (unlike notificationController, which calls assertOrganizerBooking). socketHandler.ts:242-261 join_organizer_dashboard needs no auth at all.
Impact
Leaks participant PII across companies, and keeps streaming live updates.
Fix
Call assertOrganizerBooking(booking_id, req.user.id). Authenticate sockets in io.use() with the JWT or join_token, and check ownership before socket.join.
P-08

Socket events are unauthenticated: anyone can mark any player as left and force-end a game ("Investigator Left")

HighStill open (ZV-014)
Where
socketHandler.ts:165-207 (join_lobby / join_game_group), :219 (join_cc_instance), :231, :266-285 (leave_game_group). All of them trust groupId and participantId from the client.
Impact
Emitting leave_game_group with the investigator's id closes the whole group once the 60s grace period passes. join_lobby with another id takes over their socket_id. Joining any group_* or cc-instance-* room lets an outsider read live game data. This undercuts the recent auto-close fix.
Fix
Socket middleware that checks handshake.auth.joinToken and sets socket.data.participant. Use only that identity and group, and ignore ids sent by the client.

P-11

Rate limiter keys on the proxy IP: in production the whole site shares one bucket, and joins fail with 429

HighFunctional
Where
apis/src/server.ts never calls app.set('trust proxy', …). authRateLimit.ts:28 skips every limit when NODE_ENV !== 'production'.
Impact
Behind nginx, req.ip is 127.0.0.1 for every user. otpRequestRateLimit (15 per 15 min) and otpVerifyRateLimit (10 per 15 min) then apply to all users together. In a 20-person event, participants after the ~10th get "Too many requests". If NODE_ENV is not exactly production, there is no brute-force protection at all.
Fix
Add app.set('trust proxy', 1) (one nginx hop), make sure pm2 sets NODE_ENV=production, and consider keying by IP + email.
