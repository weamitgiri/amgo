🚀 Zoventro — Production Server Setup

Step-by-step deployment of the Mystery Quest / Cook & Create platform to a Hostinger VPS, on a single subdomain.

Laravel 11 (PHP 8.3) Node 22 + Socket.IO API React (Vite) frontend MySQL — database ppp Nginx + pm2 + Certbot
⚠️ Shared hosting will NOT work. This app runs a persistent Node.js Socket.IO server (real-time game) — you need a VPS / KVM plan with root SSH. Hostinger shared hosting cannot run long-lived Node processes or websockets.

Architecture (what runs where)

Everything lives on one subdomain, e.g. game.example.com. Nginx routes each path to the right service:

PathServed byWhat it is
/Nginx staticReact frontend (lobby, game, results) — frontend/dist
/v1/*Node :6001Game API (questions, votes, scoring)
/socket.io/*Node :6001Real-time websockets (timers, presence)
/admin, /login, /apiPHP-FPMLaravel admin panel — public/
/storage/*NginxAdmin-uploaded images (roles, clues, bg)
—MySQLDatabase ppp, shared by Laravel + Node
The app path prefix is /p only in local dev (because the docroot is the parent folder). In production the docroot points straight at Laravel's public/, so the admin lives at /admin — no /p.

1 Point the subdomain (DNS)

In your DNS provider (or Hostinger hPanel → Domains → DNS), add an A record for the subdomain pointing at your VPS's public IP:

TypeNameValueTTL
AgameYOUR_VPS_IP3600

DNS can take a few minutes to a few hours. Check with ping game.example.com — it should resolve to your VPS IP.

You can also do this through the Hostinger MCP once it's connected (ask Claude to create the subdomain / DNS record for you).

2 Create & connect to the VPS

  1. Hostinger hPanel → VPS → deploy an Ubuntu 24.04 template.
  2. Note the VPS IP and set your root password / SSH key.
  3. SSH in from your computer:
ssh root@YOUR_VPS_IP

Update the system first:

apt update && apt upgrade -y

3 Install the stack

Nginx, MySQL, Git, unzip

apt install -y nginx mysql-server git unzip curl

PHP 8.3 + extensions (Laravel)

apt install -y software-properties-common
add-apt-repository -y ppa:ondrej/php
apt update
apt install -y php8.3-fpm php8.3-cli php8.3-mysql php8.3-mbstring \
  php8.3-xml php8.3-curl php8.3-zip php8.3-gd php8.3-bcmath php8.3-intl

Composer

curl -sS https://getcomposer.org/installer | php
mv composer.phar /usr/local/bin/composer

Node.js 22 + pm2

curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs
npm install -g pm2
The Node API requires Node 20.19+ or 22.12+. Confirm with node -v. Older versions break the Vite/TanStack build.

4 MySQL database

Secure MySQL, then create the database and a user (both Laravel and the Node API use this one database):

mysql_secure_installation   # set a root password, answer Y to the prompts

mysql -u root -p
CREATE DATABASE ppp CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'zoventro'@'localhost' IDENTIFIED BY 'STRONG_DB_PASSWORD';
GRANT ALL PRIVILEGES ON ppp.* TO 'zoventro'@'localhost';
FLUSH PRIVILEGES;
EXIT;
Laravel migrations create the schema (Step 6). If you have a data dump, import it with:
mysql -u zoventro -p ppp < /var/www/p/database/ppp.sql

5 Get the code onto the server

mkdir -p /var/www
cd /var/www
git clone YOUR_REPO_URL p     # clones into /var/www/p
cd /var/www/p

No git remote? Upload the project folder via SFTP to /var/www/p instead (exclude node_modules, vendor, and */dist — you'll rebuild them on the server).

6 Laravel (admin) setup

cd /var/www/p
composer install --no-dev --optimize-autoloader
cp .env.example .env    # if you don't already have a production .env

Edit /var/www/p/.env

APP_NAME=Zoventro
APP_ENV=production
APP_DEBUG=false
APP_URL=https://game.example.com

# Debugbar OFF (it exhausts PHP memory on the admin)
DEBUGBAR_ENABLED=false

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=ppp
DB_USERNAME=zoventro
DB_PASSWORD=STRONG_DB_PASSWORD

FILESYSTEM_DISK=public

# Mail + Razorpay: fill with your real production credentials

Key, migrations, storage, caches

php artisan key:generate
php artisan migrate --force
php artisan storage:link
php artisan config:cache
php artisan route:cache
php artisan view:cache

# permissions so PHP-FPM can write
chown -R www-data:www-data /var/www/p/storage /var/www/p/bootstrap/cache
chmod -R 775 /var/www/p/storage /var/www/p/bootstrap/cache
If you ever change routes/ or .env later, re-run php artisan config:clear && php artisan route:clear (or re-cache) — a stale route cache serves old routes.

7 Node API setup + pm2

cd /var/www/p/apis
npm install
npm run build      # compiles TypeScript → dist/

Edit /var/www/p/apis/.env

NODE_ENV=production
PORT=6001

DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=zoventro
DB_PASSWORD=STRONG_DB_PASSWORD
DB_NAME=ppp

# Only the live site origin
CORS_ORIGINS=https://game.example.com

JWT_SECRET=GENERATE_A_LONG_RANDOM_STRING

# Mail + Razorpay: real production credentials
Set NODE_ENV=production. The OTP brute-force rate limiter is deliberately skipped when NODE_ENV is not production — production must have it ON.

Start it with pm2

cd /var/www/p/apis
pm2 start dist/server.js --name zoventro-api
pm2 save
pm2 startup     # run the command it prints, to auto-start on reboot

Check it's alive: pm2 logs zoventro-api and curl http://127.0.0.1:6001/socket.io/?EIO=4&transport=polling (should return a JSON handshake).

8 Build the frontend

Edit /var/www/p/frontend/.env (build-time)

# Empty → API calls go to /v1 (same origin), proxied by Nginx to Node
VITE_API_BASE_URL=

# Socket.IO — same origin; Nginx proxies /socket.io to Node
VITE_SOCKET_URL=https://game.example.com

# Where admin-uploaded images are served (Laravel public/storage)
VITE_STORAGE_BASE_URL=https://game.example.com/storage

VITE_API_TIMEOUT=30000
cd /var/www/p/frontend
npm install
npm run build      # outputs static files to frontend/dist
Vite bakes these values in at build time. If you change a VITE_* value later, you must rebuild (npm run build).

9 Nginx config

Create /etc/nginx/sites-available/zoventro:

server {
    listen 80;
    server_name game.example.com;

    # React SPA is the site root
    root /var/www/p/frontend/dist;
    index index.html;
    client_max_body_size 20M;

    # --- Game API (Node) ---
    location /v1/ {
        proxy_pass http://127.0.0.1:6001;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # --- Socket.IO (websockets) ---
    location /socket.io/ {
        proxy_pass http://127.0.0.1:6001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;
    }

    # --- Laravel admin panel + API ---
    location ~ ^/(admin|login|logout|api|reload-captcha)(/|$) {
        root /var/www/p/public;
        try_files $uri $uri/ /index.php?$query_string;
    }

    # --- Uploaded media (Laravel storage) ---
    location /storage/ {
        alias /var/www/p/public/storage/;
        access_log off;
        expires 7d;
    }

    # --- PHP-FPM for Laravel's front controller ---
    location ~ \.php$ {
        root /var/www/p/public;
        fastcgi_pass unix:/var/run/php/php8.3-fpm.sock;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;
    }

    # --- React SPA fallback (everything else) ---
    location / {
        try_files $uri $uri/ /index.html;
    }
}

Enable it and reload:

ln -s /etc/nginx/sites-available/zoventro /etc/nginx/sites-enabled/
rm -f /etc/nginx/sites-enabled/default
nginx -t        # test config
systemctl reload nginx

10 HTTPS (SSL)

apt install -y certbot python3-certbot-nginx
certbot --nginx -d game.example.com

Certbot rewrites the Nginx config to serve HTTPS and auto-renews. After this, https://game.example.com is live.

Your APP_URL, VITE_SOCKET_URL and VITE_STORAGE_BASE_URL must all use https:// to avoid mixed-content and websocket failures. If you set them to http earlier, fix and rebuild the frontend + php artisan config:cache.

11 🔒 Production hardening (required)

Do NOT skip this. During development a few things were loosened for testing. They must be reverted before real users play.

a) Restore real OTPs (currently hard-coded to 123456)

Three places force the OTP to 123456 for testing:

  • apis/src/utils/otp.ts — remove the temporary return '123456'; line so the CSPRNG line runs; then npm run build in apis/.
  • app/Http/Controllers/API/AuthController.php (2 spots) & app/Http/Controllers/API/GameJoinController.php — change $otp = '123456'; back to
    $otp = str_pad(random_int(0, 999999), 6, '0', STR_PAD_LEFT);

b) Confirm the safety flags

  • NODE_ENV=production in apis/.env → OTP rate limiting is ON.
  • APP_DEBUG=false and DEBUGBAR_ENABLED=false in the Laravel .env.
  • Fresh APP_KEY and a strong JWT_SECRET are set.
  • Razorpay / Mail keys are the real production credentials, not test keys.

c) Firewall

ufw allow OpenSSH
ufw allow 'Nginx Full'
ufw enable
# Port 6001 stays internal — do NOT open it; Nginx proxies to it.

Common issues

  • 502 on /v1 or socket: Node not running → pm2 status, pm2 logs zoventro-api.
  • Websocket won't connect: the /socket.io/ Nginx block (Upgrade/Connection headers) is missing, or VITE_SOCKET_URL is wrong → fix and rebuild frontend.
  • Admin 500 / memory error: ensure DEBUGBAR_ENABLED=false; run php artisan config:clear.
  • Redirect loop at root: already fixed in routes/web.php — make sure you deployed the latest code and cleared route cache.
  • Images 404: run php artisan storage:link and check the /storage/ Nginx alias path.
  • DB connection refused: the DB user/password must match in BOTH .env (Laravel) and apis/.env (Node).

Redeploying after code changes

cd /var/www/p
git pull

# Laravel
composer install --no-dev --optimize-autoloader
php artisan migrate --force
php artisan config:cache && php artisan route:cache && php artisan view:cache

# Node API
cd apis && npm install && npm run build && pm2 restart zoventro-api

# Frontend
cd ../frontend && npm install && npm run build
✅ That's the whole flow. DNS → VPS → stack → DB → code → Laravel → Node → frontend → Nginx → SSL → hardening. Once green, the game is live on your subdomain over HTTPS with real-time sockets.
